## 2. 实施细节

### 2.1 bwrap 参数加固（`linux/bwrap.rs`）

```
--cap-drop ALL        # 卸全部 capability（配合 bwrap 自动设置的 no_new_privs）
--proc /proc          # 新 PID namespace 配新 /proc，避免 ps 泄漏宿主进程
```

顺序不变：`--ro-bind / /` → `--tmpfs /tmp` → `--dev /dev` → namespace flags → 白名单 rw bind。

### 2.2 seccomp BPF（`linux/helper.rs`）

在 helper 内安装，过滤器随 exec 继承、不可逆：

| 拒绝目标 | syscall / 参数 | 理由 |
|---|---|---|
| 自我换 namespace | `unshare` / `setns` / `mount` / `umount2` / `pivot_root` | 与 `--disable-userns` 形成双层 |
| io_uring 绕过 | `io_uring_setup` / `io_uring_enter` / `io_uring_register` | 不经 socket syscall 的网络 I/O |
| AF_VSOCK 绕过 | `socket(AF_VSOCK)` | 绕过 AF_INET/AF_INET6 检查 |

保留 AF_UNIX（relay 与 broker 依赖），保留 AF_INET（网络隔离由 netns 保证，代理 relay 需直连）。

安装失败时** fail-closed**：helper 返回错误，不裸跑目标命令。

### 2.3 能力报告

Linux 侧 `seccomp` 从 `partial` 升为 `full`（安装成功时）；`--require-full` 可据此拒绝启动。

### 2.4 测试

- `scripts/test-kernel-hardening.sh`：在 Linux（含特权容器）跑探针，断言
  `CapEff=0000000000000000`、`NoNewPrivs=1`、`Seccomp=2`、namespace inode 与宿主不同、
  `unshare`/`mount` 被拒、`/proc` 只含沙箱进程。
- `smoke-unix.sh` T18：把上述内核证据纳入三平台同形契约（macOS/Windows 按能力标注跳过）。

## 3. 不破坏现有契约的红线

1. 三平台 19 项契约检查必须继续通过，`CAP_KEYS` 键集合不变（只改值）。
2. `--proc /proc` 在受限容器不可用时必须显式降级，不得静默忽略。
3. seccomp 安装失败必须 fail-closed，不得降级为无过滤器执行。
4. 所有新断言在 macOS/Windows 按能力跳过（Warn），不计 FAIL。
