# 11 · 易用性优化方案：三平台同一层与对外交互层

> 立项日期：2026-11-17 · 基于 `docs/10` §3 的易用性评分（aisbx 3.4 / E2B 4.7）与源码定位。
> 核心判断：**易用性不够不是「命令太多」这一层的问题，而是「三平台同一性靠 CI 事后检查、
> launcher 内部循环被暴露成 CLI」两层设计造成的**。本文给出可落地的分层重构方案与迁移路径。

---

## 0. 问题定位（源码证据）

### 0.1 三平台同一层：同形靠测试兜底，不靠结构保证

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| S1 | `status` 的 JSON 在两处各写一遍 | `unix/broker.rs:468` / `win/broker.rs:952` | 字段漂移只能靠 `contract_check.py` 19 项事后发现 |
| S2 | `cfg` 分发散落 5 个命令函数 | `main.rs:144/186/235/259/277` | CLI 表面同一、能力实际不同 |
| S3 | Windows 的 `--op net` 运行时才报错 | `main.rs:188-190` | agent 必须读文档才知道平台差异 |
| S4 | 核心逻辑在 Windows 镜像重写 | `docs/08` §1：`win/broker.rs` 自带 `IssuedToken`/`decide_file`/`redeem_token`；`win/audit.rs` 复制 `core/audit.rs` | 一份逻辑两处实现 = 两份 bug |
| S5 | 联合类型用扁平结构模拟 | `common/pending.rs:12` 把 file/net 塞进一个结构 | agent 要 `switch(kind)` 再判空 |
| S6 | 能力报告是平铺 21 键 | `capabilities.rs:26 CAP_KEYS` | agent 自己写平台分支 |

### 0.2 对外交互层：把 launcher 内部循环暴露成了 CLI

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| I1 | 生命周期由调用方管理 | broker 只在 run 期间存在（`docs/09` §5） | 一次授权要 后台 run → 轮询 status → authorize → wait → 清理 |
| I2 | 同一任务反复传 `-p` | `main.rs:108 policy_arg` 被 4 个命令调用 | 寻址其实只需 task 名（`policy.pipe_name()`） |
| I3 | 三套输出通道 | `--json` 事件流 / `status` 单行 JSON / `audit.jsonl` | agent 要三套解析器 |
| I4 | 内部概念泄漏 | `--token` / `--ttl-seconds` / `--require-full` / `pipe_name` | 用户要理解实现细节 |
| I5 | 无预设、无 SDK | 每次写完整 5 段策略 JSON | 对比 Codex 三档、E2B 一行调用，门槛高一个数量级 |
| I6 | 参数解析手写 | `main.rs:101 flag_value`、`main.rs:229` 端口失败静默变 0 | 无 `--help` 细分、无类型校验、错误信息弱 |

## 1. 优化方案

### 1.1 P0 · 把「同形」下沉到类型系统

**目标**：CLI 行为不变，三平台行为不变，但同形由类型保证而非 CI 兜底。

#### (a) 平台无关协议 crate：`aisbx-protocol`

```rust
#[derive(Serialize, Deserialize)]
#[serde(tag = "kind", rename_all = "snake_case")]
pub enum Pending {
    File { path: String, access: Access, precision: Precision, attributed: bool, source: Source },
    Net  { host: String, port: u16, precision: Precision, attributed: bool, source: Source },
}

#[derive(Serialize, Deserialize)]
pub struct Status {
    pub attempt: u32,
    pub pending: Vec<Pending>,
    pub needs_approval: bool,
    pub retries: u32,
    pub violations_total: u32,
    pub backend: String,
}

#[derive(Serialize, Deserialize)]
#[serde(tag = "op", rename_all = "snake_case")]
pub enum EscRequest {
    File { path: String, access: Access, token: Option<String> },
    Net  { host: String, ip: String, port: u16 },
}

#[derive(Serialize, Deserialize)]
pub struct Decision {
    pub granted: bool,
    pub reason: String,
    pub effect: Effect,      // none | retry | in_place
    pub retry_required: bool,
}

#[derive(Serialize, Deserialize)]
#[serde(tag = "kind", rename_all = "snake_case")]
pub enum Grant {
    File { path: String, access: Access, ttl_seconds: u64 },
    Net  { host: String, port: u16 },
}
```

- 用 `#[serde(tag)]` 让 `kind` 成为判别字段，与现有 JSON 的 `kind:"file"/"net"` **向后兼容**。
- `Precision`/`Access`/`Effect` 用枚举，非法值在反序列化时直接失败。
- 契约检查改为校验这些类型的 schema，不再手抄字段清单。

#### (b) `Backend` trait 收口 `cfg`

```rust
pub trait Backend {
    fn name(&self) -> &'static str;
    fn run(&self, policy: &Policy, cmd: &[String], json: bool) -> Result<i32, String>;
    fn status(&self, task: &str) -> Result<Status, String>;
    fn escalate(&self, policy: &Policy, req: EscRequest) -> Result<Decision, String>;
    fn grant(&self, task: &str, grant: Grant) -> Result<Decision, String>;
    fn capabilities(&self) -> Capabilities;
}

#[cfg(windows)] pub fn backend() -> impl Backend { win::WinBackend }
#[cfg(target_os = "linux")] pub fn backend() -> impl Backend { linux::LinuxBackend }
#[cfg(target_os = "macos")] pub fn backend() -> impl Backend { macos::MacBackend }
```

- `main.rs` 只保留**一处** `backend()` 选择，删掉散落的 5 处 `cfg`。
- CLI 层完全不看平台；平台差异通过 `Backend` 实现体现。

#### (c) `Transport` trait 统一 UDS 与命名管道

```rust
pub trait Transport: Send {
    fn request(&mut self, body: &str) -> Result<String, String>;
    fn close(&mut self);
}
```

- Unix 实现：`UnixStream` 连接 `ctl.sock`/`esc.sock`。
- Windows 实现：`CreateFileW` 连接 `\\.\pipe\<task>-ctl`。
- broker 的裁决逻辑（`decide_file` / `redeem_token` / `status`）只留一份，消除 Windows 镜像实现。

#### (d) 能力报告结构化（兼容过渡）

```json
{
  "backend": "macos",
  "contract": "B",
  "capabilities": {
    "fs":   { "isolation": "full", "detection": "partial", "precision": "exact" },
    "net":  { "egress": "full", "proxy": "http-connect+socks5", "precision": "exact" },
    "resources": { "memory": "unavailable", "cpu": "unavailable", "processes": "unavailable" }
  },
  "legacy": { "...": "原有 21 个平铺键原样保留一期" }
}
```

- 旧键保留一期，消费方可以逐步迁移；`contract_check.py` 同时校验新旧两套。

### 1.2 P1 · 交互层引入「会话」抽象

- 新增高层命令，把重试循环收回沙箱内部：
  ```
  aisbx guard --policy p.json --approve-cmd <callback> -- <command>
  ```
  agent 只提供审批回调，不再自己起后台进程 + 轮询 + wait。
- `status` 每条 `pending` 带 `id` 与可直接回填的授权参数：
  ```json
  {"id":"p1","kind":"file","grant":{"path":"...","access":"write"},"precision":"reported"}
  ```
  由 `aisbx approve <session> --pending p1` 消费。
- 统一输出 envelope：
  ```json
  {"type":"violation|status|grant|exit","session":"...","data":{...}}
  ```
- 策略预设 `--profile read-only|workspace-write|full`（对齐 Codex/dsh 三档），`--policy` 仅覆盖。
- 用 `clap` derive 替换手写解析；`--token` 降级为内部 `__token`。

### 1.3 P2 · SDK 与体验

- Python/TS thin SDK：`with aisbx.sandbox(policy) as sb: sb.run(cmd, on_approval=cb)`。
- 错误可操作化：`status` 连不上返回 `{"error":"no-running-task","hint":"..."}`。
- 手册重构为「场景 → 一行高层命令 → 展开的等价底层调用」。

## 2. 迁移路径（不破坏现有契约）

| 阶段 | 动作 | 验证 |
|---|---|---|
| P0-a | 新建 `aisbx-protocol` crate，定义强类型 + 与现有 JSON 的双向转换 + 单测 | `cargo test --workspace`；契约检查 19 项不变 |
| P0-b | 定义 `Backend` trait + `Transport` trait，各平台实现；`main.rs` 收口到一处 `backend()` | 三平台 CI 全绿；冒烟两侧全绿 |
| P0-c | broker 裁决逻辑合并到一份；能力报告结构化（平铺键保留） | 契约检查扩展为 schema 校验；三平台全绿 |

### P0-c 实际落地记录（2026-11-17）

**已完成**：
- 新增 `core/decision_engine.rs`：把「黑名单前置 → token 快速路径 → 模式裁决」收成**纯函数**，
  返回 `Outcome{decision, audits, grant_path, mark_pending, prompt}`，平台只执行副作用。
  8 项单测覆盖六条不变量（黑名单压过 token、token 越过 Deny、Deny 终态不邀请、
  Auto 命中/未命中、Prompt 无 TTY 邀请、有 TTY 用户拒绝）。
- **Unix 侧 `decide_file` 已接入引擎**，95 行重复逻辑降为 37 行副作用执行；
  macOS 全量冒烟 72 PASS / 0 FAIL，契约检查通过 → 外部行为等价。
- 能力报告新增 `aisbx_protocol::Capabilities::groups()` 结构化视图（fs/net/resources/detection
  四组），**`report()` 的平铺 21 键与 CLI 输出完全不变**；10 项协议单测覆盖分组与缺失降级。

**未完成（诚实标注，不假装已合并）**：
- Windows 侧 `win/broker.rs::decide_file` **仍保留自己的实现**，未接入引擎。
  原因：①本机无 Windows 内核，无法本地验证；②Windows 审计事件带 `requested_by` 字段、
  token 兑换不校验 `command_id`、ACL 落地语义与 Unix 不同，直接替换风险高于收益。
  当前状态由 `Contract B` 的 19 项跨平台契约检查与 Windows CI 的 97 项断言保证同形。
  后续应在有 Windows 真机的环境下逐条对齐后再合并。
- `aisbx capabilities --structured` CLI 标志未加（P1 再接），当前只提供库级 API。
| P1 | `guard` 高层命令 + `status` 增 `id`/`grant`（旧字段保留） | 冒烟两侧补断言 |
| P2 | SDK + profile + 文档重构 | — |

**红线**：每一步都必须保持 `scripts/contract-baseline.json` 的 19 项检查通过；
平台差异只能结构化体现在能力报告里，不得静默降级；审批回调必须能被 agent 显式控制。

## 3. 关键取舍

1. **「三平台同一」≠「能力相同」**：macOS 资源限制 `unavailable` 是内核事实，正确做法是能力画像 + 启动前拒绝（`--require-full`），不是硬凑三种实现。
2. **易用性不能牺牲 fail-closed**：`guard` 的审批回调必须显式提供；无 TTY 时仍拒绝，不自动放行。
3. **兼容优先于纯粹**：平铺能力键、`kind` 判别字段、`status` 旧字段都保留一期，让 agent 侧有迁移窗口。
4. **先收口、后扩展**：P0 只改内部结构不改外部行为，确认三平台 CI 全绿后再加 P1 命令，避免「重构 + 新功能」同时引入的归因困难。
