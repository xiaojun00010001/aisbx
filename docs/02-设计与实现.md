# aisbx 设计与实现(v0.1)

面向 agent 框架的 Windows 本地沙箱:**LowBox(AppContainer)token + Job Object + 授权 broker**,单一静态二进制,Rust 实现,无管理员要求。

## 1. 架构与机制映射

```text
┌────────────────────────────────────────────────────────────┐
│ aisbx run(宿主 launcher)                                    │
│                                                            │
│  策略(policy.json)                                          │
│    ├─ ① package SID 生成(每任务一次,S-1-15-3-4096-...)       │
│    ├─ ② ACL 白名单:write 目录(M)/ read 目录(RX)/ 策略文件(R) │
│    ├─ ③ CheckNetIsolation 回环例外(不开 internet capability) │
│    ├─ ④ NtCreateLowBoxToken(packageSID + caps,低完整性)     │
│    ├─ ⑤ Job Object:内存×2/CPU 万分比/进程数/KILL_ON_CLOSE/UI │
│    ├─ ⑥ broker 命名管道(DACL 仅含 package SID)              │
│    └─ ⑦ CreateProcessAsUserW(CREATE_SUSPENDED→入Job→Resume) │
└────────────────────────────────────────────────────────────┘
        │ token 继承:bash→gcc→curl 全部在同一 AppContainer+Job 内
        ▼
  沙箱内进程:越界文件 ACCESS_DENIED / 外网连接失败
        │ 唯一可打开的通道
        ▼
  aisbx escalate --path X --access read   (经 broker 管道)
        │ {op,path,access}
        ▼
  broker 裁决:deny_escalation 黑名单 fail-closed →
  模式(prompt:问用户,非TTY fail-closed / auto:allow_escalation 白名单 / deny)
        │ 授权 = 对具体路径写 ACL(icacls /grant *SID:R|M)
        ▼
  审计 JSONL + 授权响应;后续真实 syscall 直接通过,不再打断
```

关键决策:

| 决策 | 选择 | 理由 |
|---|---|---|
| token 创建 | `NtCreateLowBoxToken` 而非 `CreateAppContainerProfile` | 不写注册表零残留,亚毫秒级,会话级资产一次生成全程复用(每次工具调用只是 CreateProcess) |
| 子进程约束 | token + Job 双继承,不设 BREAKAWAY_OK | bash 启动的任意子孙进程自动继承隔离与预算,零额外配置 |
| ACL 实现 | icacls(MVP) | 稳定免手写 SD;生产可换 SetNamedSecurityInfoW |
| 管道安全 | SDDL `D:(A;;GA;;;<packageSID>)` | 沙箱内只有本任务进程树能打开授权通道 |
| 网络 | 零 capability + 回环例外;internet=true 注入 capability SID(S-1-15-3-1/3) | 内核 WFP 层丢弃 socket,进程内无法绕过 |
| 提权语义 | 授权 = 精确路径 ACL / 拒绝 = 与无权限一致 | 不提升进程权限,符合"权限边界始终在 broker" |
| 黑名单 | `deny_escalation` 先于用户提示判定 | 防用户手滑击穿 .ssh / ProgramData\ssh 等敏感区 |

## 2. 策略契约(aisbx-policy)

见 `examples/policy.example.json`。字段:task / filesystem{write,read,deny_escalation,allow_escalation,escalation} / network{loopback,internet} / resources{memory_mb_per_process,memory_mb_total,cpu_percent,active_processes,max_iops} / broker{audit_log,pipe_name}。

## 3. agent 框架接入(轻接入)

三种接法,从浅到深:

1. **工具包装**:把 agent 的 bash/exec 工具调用替换为
   `aisbx run -p task.policy.json -- cmd /c <原命令>`;
   退出码原样透传,`--json` 输出结构化事件(spawned/exit/sid)。
2. **提权闭环**:沙箱内脚本对越界路径先调
   `aisbx escalate -p task.policy.json --path C:\x --access write`,
   退出码 0=已授权(重试原操作)/ 1=被拒(向模型报告原因)。
3. **事件流**:`--json` + audit JSONL 可直接订阅做观测面。

## 4. 已知限制与路线图

- [ ] **磁盘 IOPS 限速未实现**:`SetIoRateControlInformationJobObject` 需补 IO 特性(framework 集成点已在 job.rs 预留注释)。
- [ ] **网络按主机授权缺 WFP**:`network.internet=false` 时 broker 对 net 请求 fail-closed 并提示;按 IP:port 放行需 WFP 规则(要管理员或 FWPM 权限),路线图用「broker 加规则 + 任务内复用」实现。
- [ ] **进程内 hook(shim)未实现**:MVP 提权由工具显式调 `aisbx escalate` 触发;syscall 级同步拦截(挂 NtCreateFile,授权后句柄回填)是 v0.2,协议已按此设计。
- [ ] Everyone SID 可写的目录防不住(与 Codex 已知限制相同,token 继承的默认 DACL 所致)。
- [ ] 提权路径匹配用展开后的前缀匹配,未做符号链接规范化(MVP:ACL 在真实对象上,逃逸面有限);v0.2 broker 侧加 GetFinalPathNameByHandle 规范化。
- [ ] 未在真实 Windows 上回归(本机 macOS 交叉 check 通过);需要 Windows 10 1809+ 验证矩阵。
