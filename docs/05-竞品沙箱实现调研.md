## 0. 结论速览

1. **我们最关键的判断被三家证实**：Claude Code（srt）、Codex、dsh **都没有**「运行中按具体路径修改 OS 文件 PEP」的能力。srt 运行中只能改网络规则（文件规则已固化在 Seatbelt profile / bwrap argv / Windows ACE）；Codex 与 dsh 的「用户同意」是**以更宽松策略重新执行命令**。因此 `docs/04` §3 的「静态规则集 vs 运行时精确放行」分析成立，C10（授权后真实 syscall 立即生效）仍是差异化空白，**不应为了对齐竞品砍掉**。
2. **但存在一个我们漏掉的更实用路径**：接受「授权后重启命令」语义即可完全照抄三家（bwrap/Landlock、Seatbelt），**无需专用 UID、无需 root**。建议新增 `portable` 降级模式，与 `strict`（对象侧可变 ACL，完整能力）并行，先做 portable 降低阶段 2/3 风险。
3. **必须修正 Linux 逃逸面**：bwrap 的只读 bind 可被沙箱内进程自建 user namespace 后 `umount` 拆掉。srt 用 seccomp 第二过滤器禁 `unshare`/`clone(CLONE_NEWUSER|CLONE_NEWNS)`/`setns`/`mount`/`umount2`/`pivot_root`/`clone3`，并把 `user.max_user_namespaces=0`。`docs/04` §4.2 原本只写「seccomp 白名单」，粒度不足。
4. **必须把「降级」升级为一等契约**：Codex 检查 `RulesetStatus::NotEnforced` 直接拒绝执行，dsh 用 `--probe` + `SANDBOX_UNAVAILABLE` + `full/partial` 如实上报，srt 有 `checkDependencies()`。我方应新增 C23 `aisbx capabilities --json` 与 `--require-full`，而不是仅靠日志标注。
5. **工程组织需修正一处**：seccomp/Landlock 必须在 bwrap 命名空间**建立之后、进程内**应用，Codex 用独立 helper 二进制（`codex-linux-sandbox`），srt 用 `apply-seccomp` multicall（`ARGV0` 分发）。我们当前 `[[bin]] aisbx` 单入口不够；建议**单二进制 multicall**（`AISBX_ROLE=helper`），保持单 crate 单产物。
6. **网络维度有成熟参考可抄**：三家一致走「仅允许连本地代理端口 + 宿主 HTTP/SOCKS5 代理 + 域名白名单」。srt 还给出 resolved-address check（防 DNS rebinding / 云元数据 / 私网）、per-command 128bit `commandId` 绑定、ask callback。阶段一能力不变，但接口要预留。
7. **审计归因可补强**：srt 的 `SandboxViolationStore` + `commandId` 避免长命令串台；我们的结构化应答/审计比 Codex 的 stderr 字符串匹配更可靠，但缺 `command_id` 字段，阶段 1 下沉 `core` 时一并加。

## 2. 三家实现拆解

### 2.1 Claude Code → `sandbox-runtime`（srt）

| 维度 | 实现 |
|---|---|
| 定位 | OS 级、无容器的轻量沙箱；CLI `srt <cmd>` 与 TS 库 `SandboxManager`；Claude Code 的 sandboxed bash 后端 |
| macOS | `sandbox-exec` + 动态生成 SBPL profile；系统违规日志 store 做实时告警；开关 `allowPty`、`allowAppleEvents`、`enableWeakerNetworkIsolation`（trustd） |
| Linux | `bubblewrap`（只读根 + 显式可写 bind）+ network namespace 隔离 + 打包的 seccomp BPF 过滤器（x64/arm64，multicall `apply-seccomp`） |
| Windows（alpha） | **专用本地账户 `srt-sandbox` + WFP 出站围栏（按账户 SID）+ write-restricted token + NTFS ACE**；需一次性 UAC 安装 `windows-install` |
| 文件系统语义 | 读 = deny-then-allow（`allowRead` 优先）；写 = allow-only（`denyWrite` 优先，**空 allowlist = 无写权限**） |
| 网络 | 仅允许连宿主代理：Linux 移除 netns、代理的 Unix socket 被 bind-mount 进沙箱；macOS profile 只放行特定 localhost 端口；HTTP + SOCKS5 代理执行域名 allow/deny |
| **运行中变更** | `--control-fd` 可更新网络列表、ask callback、MITM 设置（下一次连接生效）；**明确说明文件系统规则运行中不可变**（已在 profile / bwrap argv / Windows ACE 中） |
| 用户授权 | `SandboxAskCallback(host, port)`：既非 allow 也非 deny 的目的地问用户；`registerCommandNetworkLists` 用 ≥128bit 随机 `commandId` 绑定单次调用白名单 |
| 加固细节 | resolved-address check 拒绝 loopback / link-local / 云元数据 / 本机地址 / IPv4-mapped IPv6 / NAT64；`requireHostMatch`、ambiguous request target 拒绝；seccomp 第二过滤器禁 userns/mount/setns/pivot_root、`clone3`→ENOSYS、`user.max_user_namespaces=0` |
| 依赖与探测 | Linux 需 bwrap ≥0.5（部分特性 ≥0.8）、socat、ripgrep；`checkDependencies()` 检查版本与权限；Ubuntu 24.04+ `kernel.apparmor_restrict_unprivileged_userns` 会剥离 userns capabilities；root 调用者需 `CAP_SETFCAP`，否则全部命令 `Operation not permitted` |
| 已知限制（自述） | 共享内核；默认无 TLS 检查可被域前置绕过；允许域的宽松凭据可外泄；部分程序不遵守 `HTTP_PROXY`（Node `fetch` 需 `NODE_USE_ENV_PROXY=1`）；Windows 受限令牌导致 **Schannel 不可用**（curl.exe / PowerShell Invoke-WebRequest / .NET / cargo 的 HTTPS 失效） |
| 可直接参考的文件 | `src/sandbox/linux-sandbox-utils.ts`、`macos-sandbox-utils.ts`、`http-proxy.ts`、`socks-proxy.ts`、`sandbox-violation-store.ts`、`windows-sandbox-utils.ts`、`vendor/seccomp-src/`、`docs/srt-proxy.md` |

### 2.3 dsh = DeepSeek Harness

| 维度 | 实现 |
|---|---|
| 架构 | 「一切皆插件」；沙箱是可替换 seam `ctx.sandbox`，`LocalSandboxProvider.confine(argv, policy)` 把**确切 argv** 包装成 `ConfinedArgv`；`SandboxMode = read-only / workspace-write / danger-full-access` |
| Linux | 优先 `bwrap`，否则回退自带 **C11 native `landlock-run`**（`--ro` / `--rw` / `--probe`，内核 ≥5.13；失败输出 `landlock-run:` 前缀并以 `125` 退出以便与子进程失败区分） |
| macOS | `sandbox-exec` + 动态生成的 Seatbelt profile；`read-only` 只放行 `/dev/null` 写，`workspace-write` 放行 canonical workspace 根与系统临时目录；`sandbox-exec -p` 测试 profile 探测，不可用/被内核拒绝即 **fail-closed** |
| Windows | `CreateRestrictedToken(WRITE_RESTRICTED + DISABLE_MAX_PRIVILEGE)` + Low IL；**Workspace Write SID**（由工作区路径确定性派生）+ **每会话随机 Temp Write SID**；授予目录加 Low no-write-up 标签 + world SID 的 `FILE_DELETE_CHILD` deny；配套 `diagnose-windows-sandbox-acl` 诊断/回滚技能 |
| 网络 | **明确标注 Not enforced**（Linux/Windows）；Windows 读限制也标注 Not enforced（ambient SIDs 允许读）；NTFS hard link aliasing 可绕过写限制 |
| 强制级别 | `SandboxEnforcement` 如实上报 `full` / `partial`（旧 Landlock ABI、Windows ACL 边界算 partial），**要求绝对保证的消费方必须拒绝 partial**；无可用后端抛结构化 `SANDBOX_UNAVAILABLE`，绝不降级为无约束执行 |
| 审批 | `ctx.approval` seam：沙箱拒绝后可请求用户同意，以更宽松 `sandboxPolicy` 重试；第三方资料称规则为「重试目标必须严格宽于当前模式，且只允许基于真实发生过的拒绝发起，不允许绕过沙箱反复试探」（二手，需核实） |
| fs/subprocess 统一 provider | 文件系统与进程执行共享抽象，换成 E2B 远程沙箱时 Bash/PTY/LSP 整体搬迁，无需为每个能力写平台分支 |
| 状态 | Developer Preview（rc），接口会变；底层 Cordis 为 vendor 引入 |
| 可直接参考的文件 | `packages/sandbox/sandbox-local/src/index.ts`、`profiles.ts`、`tests/{bwrap,seatbelt}.e2e.ts`、`packages/sandbox/sandbox-windows-acl/src/{token,grant,acl,spawn}.ts`、`native/system`（landlock-run）、`packages/sandbox/sandbox/README.md` |

## 4. 对 `docs/04` 的影响

### 4.1 坚持不改（调研反而验证了差异化）

- **C06–C10 的 broker 闭环不能砍**。三家把「用户同意」放在 agent 层或代理层，文件访问授权都以「重启命令」实现。我们的「宿主签发一次性 token → 沙箱内消费 → 落 ACL → 下一次真实 syscall 立即放行」是空白能力，也是 `docs/01` 结论在 2026 年最新实现面前仍然成立。
- **Windows 继续用 AppContainer + LowBox + Job**，不要换成 srt 的「专用账户 + WFP」或 dsh 的 `WRITE_RESTRICTED` token：前者需一次性 UAC，后者不强制网络且明确「读取不强制」，而且两者都没有资源预算。我们的方案无需管理员且能力更全。
- **单 crate + cfg 的工程组织**（方案 A）仍成立。Codex 的多 crate 与 dsh 的插件 seam 是为「大体量 + 可替换后端」服务的；我们阶段一代码量小，保留薄 `backend` 边界即可，迁移路径不变。

## 5. 关键权衡决策记录：strict / portable 双模式

| | `strict`（方案 v1 原路径） | `portable`（本次新增） |
|---|---|---|
| 文件 PEP | 专用 UID + 对象侧可变 ACL | bwrap/Landlock（Linux）、Seatbelt（macOS）静态规则集 |
| 特权 | Linux 需 `CAP_SETUID` 或 userns+subuid；macOS 需 root | 无需特权 |
| C02–C07、C17–C21 | ✅ | ✅ |
| C08–C10 运行中提权 | ✅（真实 syscall 即时生效） | ⚠️ 降级为「用户同意后以更宽松策略重跑命令」，需显式登记 |
| 实现复杂度 | 高（身份管理、ACL 生命周期、清理） | 低（可直接参考三家成熟参数/profile） |
| 与竞品对齐 | 差异化 | 一致 |

**决策**：两模式并存，`strict` 为默认与验收基线（用户要求「同样的能力」，C10 不可降级），`portable` 作为无特权环境/快速验证路径。实施顺序调整为 **阶段 2a 先 portable（打通三平台 CI 与能力矩阵）→ 阶段 2b strict（补齐 C08–C10）**，把高风险的特权与 ACL 生命周期工作后移，同时保证最终能力不打折。能力报告必须写明当前模式与每项 full/partial。

## 6. 修订后的阶段计划（增量）

| 阶段 | 相对 v1 的变化 |
|---|---|
| 0（已完成） | 不变：`windows-sys` target 分区、`backend` 骨架、三平台 check 矩阵 |
| 1 | `core` 下沉时增加 `command_id`、能力报告数据结构（`CapabilityReport`）、依赖探测接口 |
| 2a | 新增：Linux portable 后端（bwrap+Landlock+反逃逸 seccomp+netns）+ `smoke-linux.sh`；multicall helper 入口 |
| 2b | Linux strict 后端（UID+POSIX ACL+cgroups+UDS broker） |
| 3a | 新增：macOS portable 后端（SBPL 模板+生成器+单测+违规日志） |
| 3b | macOS strict 后端（UID+APFS ACL+setrlimit+UDS broker） |
| 4 | 三平台 CI 全开；`capabilities --json` 与能力矩阵报告；Windows 侧补 M11 |

验收增量：`capabilities --json` 在每台 runner 输出并被 CI 断言；`--require-full` 在 partial 模式下必须拒绝启动；portable 模式的 C08–C10 在报告中必须标 `partial`，不得计入「全部通过」。

## 7. 风险补充登记

| # | 风险 | 缓解 |
|---|---|---|
| R12 | bwrap 只读 bind 被沙箱内自建 userns + mount/umount 拆除 | M1 的 seccomp 反逃逸过滤器 + `user.max_user_namespaces=0`；CI 增加「尝试 unshare/mount 必须失败」断言 |
| R13 | 发行版/内核差异导致沙箱「看似启动、实则未生效」 | M2/M3/M8：ABI 与依赖探测 + `NotEnforced` 检查 + `--require-full` + `SANDBOX_UNAVAILABLE` 式结构化失败 |
| R14 | macOS 为让 Go/Node 工具正常工作而放行 trustd/pty/AppleEvents，可能打开数据外泄或代码执行通道 | 例外逐项登记并默认关闭（对齐 srt 的 `enableWeakerNetworkIsolation` / `allowAppleEvents` 语义），能力报告标 partial |
| R15 | 代理方案的 DNS rebinding / 云元数据 / 私网绕过 | M10 resolved-address check；原理矩阵 §4b 的 SSRF 事故清单作为测试用例 |
| R16 | 竞品均处于 Beta/Preview，借鉴的 API 与参数会变 | 只固化「机制与不变量」，不写死版本；profile/参数生成器加真机单测 |
